# Contributing to The Library of Babel

Open an issue for a bug or proposed feature. For rendering bugs, include the browser,
device, exact movement/view or teleport sequence and screenshots where possible.
Avoid attaching private save data or text you cannot share.

## Change workflow

1. Start a new branch from current `main` for each feature or fix.
2. Make focused changes, update the relevant documentation and run applicable
   [checks](docs/DEVELOPMENT.md).
3. Push the branch and open a pull request against `main`. Explain the problem,
   resulting behavior, validation and known limitations.
4. Wait for explicit approval from the repository owner. Do not merge or enable
   automatic merging before approval.
5. After approval, squash-merge the PR. Do not merge the Babylon backup branch.

Use The Library of Babel consistently in player-facing text and documentation.
Keep README focused on the concept, model specifications, getting started and player
features. Put implementation details in `docs/` and change notes in `CHANGELOG.md`.

Contributions must be yours to submit and compatible with the project's MIT license.
Document any third-party asset's origin and license, and retain required notices.
Read the [attribution policy](docs/ATTRIBUTION.md) before adding literary material.
